# HITRAG Frontend End-to-End Documentation

## Overview

**HITRAG** (Harare Institute of Technology RAG Assistant) is an AI-powered knowledge interface designed specifically for students, lecturers, and administrators at the Harare Institute of Technology (HIT). All responses generated by HITRAG are strictly grounded in official HIT documents, regulations, and institutional handbooks, with mandatory citation tracking for every claim.

This document details the complete end-to-end architecture, design system specifications, component hierarchy, routing rules, and mock API integration layer established in the frontend codebase.

---

## Technical Stack

- **Framework**: Next.js 14 (App Router)
- **Language**: TypeScript (`strict: true`)
- **Styling**: Tailwind CSS (Custom HIT Design Token System)
- **Icons & Visuals**: Inline SVG document glyphs & micro-animations
- **Typography**: Space Grotesk (`font-display`), Inter (`font-body`), IBM Plex Mono (`font-mono`)

## Core Functional Components

### 1. Citation Tags & Access Tiers (`components/ui/citation-tag.tsx`)
- **`CitationTag`**: Monospace button formatted as `[1]`, `[2]` using amber tint (`bg-hit-amber/10 text-hit-amber`). Tapping triggers the expanded citation drawer.
- **`TierPill`**: Indicates access tier levels:
  - `Public`: Neutral gray pill (`bg-hit-border/60 text-hit-text-secondary`)
  - `Student` / `Lecturer` / `Admin`: Solid navy pill (`bg-hit-blue text-white`)

### 2. Expanded Citation Detail Drawer (`components/chat/citation-drawer.tsx`)
- **Desktop Behavior**: Right-side slide-in panel (`w-96 h-full border-l`) that sits alongside the message feed without obscuring user context.
- **Mobile Behavior**: Bottom sheet drawer (`max-h-[85vh] rounded-t-2xl border-t`) with a subtle drag handle and backdrop overlay.
- **Content**: Source document title in monospace typeface, exact verbatim excerpt with amber left border (`border-l-4 border-l-hit-amber`), metadata row (department, document type, last updated), access tier pill, and a `"View full document"` action.

### 3. Restricted Access Boundary Notice (`components/ui/restricted-boundary-notice.tsx`)
- Triggered when a query asks for information outside the user's role access (e.g. a student asking about staff salary scales).
- **Design Philosophy**: Uses a muted red `#B5482D` left-edge grounding line (`GroundingRule`). Formatted with a calm, neutral institutional tone (*"This query pertains to institutional records outside the access permissions of student accounts."*) and provides a suggested office contact card (e.g. *HIT Human Resources & Staff Relations Office*).
- **Security Guarantee**: Zero document title or excerpt content is revealed.

### 4. Role-Aware Empty State (`components/chat/empty-state.tsx`)
- Displayed when starting a new conversation.
- Understated centered layout with 3–4 role-tailored plain text rows (e.g., *"When does registration close?"*, *"What happens if I fail a module?"*).
- Footer tag reinforcing grounding: *"Answers are drawn from official HIT documents and always cited."*

### 5. Scope Transparency Indicator (`components/chat/chat-input.tsx`)
- Located near the input bar to inform users of the active retrieval permissions for their session (e.g., `Active Retrieval Scope: Public + Student` or `Public + Lecturer`).

## Mock Data & Service Layer (`lib/api.ts`)

To prepare for backend integration (e.g., FastAPI / BigQuery vector search), all components consume data through functional service calls in `lib/api.ts`:

- `getCurrentUserRole()`: Resolves active role (`Student`, `Lecturer`, `Admin`, `Public`).
- `setCurrentUserRole(role)`: Updates session role and dispatches `hitrag_role_changed` events.
- `getConversations()`: Returns mock conversations grouped by date.
- `getConversationById(id)`: Returns specific conversation messages.
- `sendMessage(conversationId, text)`: Simulates 800ms API latency and returns grounded assistant responses with citations or restricted notices.
